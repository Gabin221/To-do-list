# To-do-list

+ structure:
  + page d'affichage des tâches (ajout, suppression et modification via des icônes faisant apparaître une modale permettant d'afficher le formulaire adéquat)
  + différentes priorités:
    + basse
    + standard
    + haute
    + prioritaires  
  Ces différentes priorités sont triées par date à chaque fois. Les tâches de priorités basse, standard et haute sont triées uniquement par date. Les tâches prioritaires sont au dessus des priorités moindres et triées par date également. Ce niveau de priorité est à utiliser avec modération, l'idée est d'en utiliser peu afin de les avoir en permanance sous les yeux.
  + une zone en dessous permet de regroupées les tâches semi-validées (validées mais sans que ce soit pleinement satisfaisant) mais non supprimées, l'idée étant de garder un historique de ce qui a été réalisé, utile par exemple dans un suivi pour un projet
  + une zone en dessous permet de regroupées les tâches validées mais non supprimées, l'idée étant de garder un historique de ce qui a été réalisé, utile par exemple dans un suivi pour un projet
+ éléments:
  + la mémoire est locale à la machine sur laquelle est installé l'application, la confidentialité étant la priorité de ce projet
  + possibilité de faire des sous-listes
+ idées d'amélioration:
  + proposer à l'utilisateur de choisir entre mémoire locale on en ligne
  + proposer à l'utilisateur de choisir ou non de conserver les tâches terminées
